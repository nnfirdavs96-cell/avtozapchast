Путь одной задачи: от ветки до боевого сайта
Шесть шагов, которые повторяются для каждой новой функции магазина
1
Завели ветку под задачу
Имя ветки — про задачу, а не про себя: korzina, а не firdavs2.
git switch -c korzina
2
Поработали и закоммитили
Столько коммитов, сколько законченных мыслей. Ветка своя — мешать некому.
git add korzina.php git commit -m "Корзина: подсчёт суммы"
3
Отправили ветку на GitHub
Теперь работа не только на вашем ноутбуке. Сгорел ноутбук — код цел.
git push -u origin korzina
4
Открыли pull request
«Предлагаю влить korzina в main». Заголовок и описание — что сделано и как проверить.
Кнопка «Compare & pull request» на GitHub
5
Ревью и правки
Замечания приходят в PR. Правите у себя, коммитите, пушите — PR обновляется сам.
git commit -m "Правка по ревью: проверка количества" git push
6
Слили и удалили ветку
Squash-merge: вся ветка ложится в main одним аккуратным коммитом.
Кнопка «Squash and merge», затем «Delete branch»
Зачем всё это одному человеку: pull request — это ваша пауза перед тем, как тронуть работающий магазин. Вы видите весь свой диф целиком и часто находите там лишнее до того, как его увидит покупатель.
