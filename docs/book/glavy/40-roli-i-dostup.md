# Глава 40. Роли и разграничение доступа

> **Часть VIII. Магазин** · Глава 40 из 60
> [← Глава 39](39-registraciya-i-vhod.md) · [Глава 41 →](41-oformlenie-zakaza.md)

## 🎯 Зачем эта глава

В магазине четыре типа людей, и каждому нужно своё:

| Кто | Что можно |
|---|---|
| **Покупатель** | Каталог, корзина, свои заказы |
| **Продавец** | Плюс: свои товары, свои заказы, свой баланс |
| **Менеджер** | Плюс: все заказы, модерация товаров |
| **Администратор** | Всё, включая настройки и других пользователей |

Задача главы — сделать так, чтобы каждый видел только своё. И, что важнее, —
**чтобы никто не мог попасть в чужое, даже зная адрес страницы**.

Это тема, где ошибка стоит дорого. Скрыть ссылку в меню — не защита.
Разберём, как делать правильно.

## 📖 Главное правило

> **Прятать — не значит защищать.**

Убрали кнопку «Админка» из меню для покупателя? Он всё равно наберёт
`/admin/` в адресной строке и попадёт туда.

Проверка прав должна стоять **в самом начале каждой защищённой страницы**,
на сервере. Меню — это удобство, а не безопасность.

Запомните формулировку: **скрытие ссылки — это вежливость, проверка на сервере —
это защита.**

## 📖 Роли

Мы завели их ещё в главе 31:

```sql
rol ENUM('pokupatel','prodavec','manager','admin') NOT NULL DEFAULT 'pokupatel'
```

Простая схема «одна роль на человека» покрывает большинство магазинов.
Есть и сложнее — набор отдельных разрешений, — но начинать стоит с ролей:
их легко понять и трудно запутать.

### **Функции проверки**

```php
<?php
// includes/prava.php
declare(strict_types=1);

/** Роли по возрастанию полномочий. */
const IERARHIYA_ROLEY = ['pokupatel' => 1, 'prodavec' => 2, 'manager' => 3, 'admin' => 4];

function rol(): string
{
    $p = tekushiy_polzovatel();
    return $p['rol'] ?? 'gost';
}

/** Роль ровно такая. */
function rol_est(string $nuzhnaya): bool
{
    return rol() === $nuzhnaya;
}

/** Роль не ниже указанной. Админ проходит везде. */
function rol_ne_nizhe(string $minimum): bool
{
    $moya = IERARHIYA_ROLEY[rol()] ?? 0;
    $nado = IERARHIYA_ROLEY[$minimum] ?? 99;
    return $moya >= $nado;
}

/** Требовать вход. Не вошёл — на страницу входа, с возвратом. */
function trebuetsya_vhod(): void
{
    if (!voshel()) {
        $_SESSION['posle_vhoda'] = $_SERVER['REQUEST_URI'] ?? '/';
        header('Location: /vhod.php');
        exit;
    }
}

/** Требовать роль не ниже. Иначе честная 403. */
function trebuetsya_rol(string $minimum): void
{
    trebuetsya_vhod();

    if (!rol_ne_nizhe($minimum)) {
        http_response_code(403);
        require __DIR__ . '/../403.php';
        exit;
    }
}
```

Применение — **первой строкой** защищённой страницы:

```php
<?php
require_once __DIR__ . '/../includes/bootstrap.php';
trebuetsya_rol('manager');      // дальше только менеджеры и админы

// ...остальной код страницы
```

⚠️ **Именно первой строкой.** Если поставить проверку после запроса к базе
или после вывода чего-то на экран, часть работы уже выполнится — и данные могут
утечь в ответе.

## 📖 Владение: сложнее, чем роль

Роль отвечает на вопрос «кто ты». Но есть второй вопрос: **«твоё ли это?»**

Продавец Ахмад имеет роль `prodavec` и право редактировать товары.
Но **только свои**. Открыв `/seller/tovar.php?id=99`, где 99 — товар Сафара,
он не должен ничего увидеть.

```php
/** Может ли текущий пользователь трогать этот товар. */
function mozhno_redaktirovat_tovar(array $tovar): bool
{
    $ya = tekushiy_polzovatel();
    if ($ya === null) return false;

    // Менеджер и админ — любой товар
    if (rol_ne_nizhe('manager')) return true;

    // Продавец — только свой
    if ($ya['rol'] === 'prodavec') {
        $moy_magazin = zapros_znachenie(
            'SELECT id FROM prodavcy WHERE polzovatel_id = ?', [$ya['id']]
        );
        return $moy_magazin && (int) $tovar['prodavec_id'] === (int) $moy_magazin;
    }

    return false;
}
```

И на странице:

```php
<?php
require_once __DIR__ . '/../includes/bootstrap.php';
trebuetsya_rol('prodavec');

$tovar = tovar_po_id((int) ($_GET['id'] ?? 0));

if ($tovar === null) {
    http_response_code(404);
    exit('Товар не найден');
}

if (!mozhno_redaktirovat_tovar($tovar)) {
    http_response_code(403);
    exit('Это не ваш товар');
}
```

### **Ошибка, которую совершают почти все**

```php
// ❌ Проверили роль, но не владение
trebuetsya_rol('prodavec');
$tovar = tovar_po_id((int) $_GET['id']);
// ...и сразу редактируем
```

Любой продавец сможет править товары любого другого, просто подобрав номер
в адресе.

Эта дыра называется **IDOR** — небезопасная прямая ссылка на объект.
Она входит в первую десятку самых частых уязвимостей, и находят её обычно
не хакеры, а любопытные пользователи.

**Правило: проверяйте не только «кто ты», но и «твоё ли это».**

### **Способ надёжнее: фильтровать в запросе**

Ещё лучше — не проверять после, а **сразу не доставать чужое**:

```php
function moy_tovar(int $tovar_id): ?array
{
    $ya = tekushiy_polzovatel();

    // Менеджеру отдаём любой
    if (rol_ne_nizhe('manager')) {
        return tovar_po_id($tovar_id);
    }

    // Продавцу — только с проверкой владения прямо в запросе
    return zapros_odin('
        SELECT t.*
        FROM tovary AS t
        INNER JOIN prodavcy AS p ON p.id = t.prodavec_id
        WHERE t.id = ? AND p.polzovatel_id = ?
    ', [$tovar_id, $ya['id']]);
}
```

Чужой товар просто **не найдётся** — и забыть проверку невозможно, она
встроена в запрос.

**Это лучший подход.** Защита, которую нельзя случайно пропустить, надёжнее
защиты, о которой нужно помнить.

## 📖 Личный кабинет

```php
<?php
// kabinet.php
require_once __DIR__ . '/includes/bootstrap.php';
require_once __DIR__ . '/includes/prava.php';

trebuetsya_vhod();
$ya = tekushiy_polzovatel();

// Заказы только свои — условие в запросе, а не проверкой после
$zakazy = zapros('
    SELECT id, nomer, summa_itogo, status, sozdan
    FROM zakazy
    WHERE polzovatel_id = ?
    ORDER BY sozdan DESC
    LIMIT 20
', [$ya['id']]);

$zagolovok = 'Личный кабинет — ' . SAIT_NAZVANIE;
require __DIR__ . '/includes/header.php';
?>

<h1>Здравствуйте, <?= e($ya['imya']) ?></h1>

<div class="kabinet-razdely">
    <a class="razdel" href="kabinet.php">Мои заказы</a>
    <a class="razdel" href="profil.php">Профиль</a>

    <?php if (rol_est('prodavec')): ?>
        <a class="razdel" href="/seller/">Мои товары</a>
        <a class="razdel" href="/seller/finance.php">Баланс</a>
    <?php endif; ?>

    <?php if (rol_ne_nizhe('manager')): ?>
        <a class="razdel" href="/admin/">Админка</a>
    <?php endif; ?>
</div>

<h2>Мои заказы</h2>

<?php if (empty($zakazy)): ?>
    <div class="pusto">
        <p>Заказов пока нет.</p>
        <a class="knopka" href="/">Перейти в каталог</a>
    </div>
<?php else: ?>
    <table class="spisok">
        <thead>
            <tr><th>Номер</th><th>Дата</th><th>Сумма</th><th>Статус</th><th></th></tr>
        </thead>
        <tbody>
        <?php foreach ($zakazy as $z): ?>
            <tr>
                <td class="mono"><?= e($z['nomer']) ?></td>
                <td><?= date('d.m.Y', strtotime($z['sozdan'])) ?></td>
                <td class="mono"><?= somoni((int) $z['summa_itogo']) ?></td>
                <td><span class="status s-<?= e($z['status']) ?>">
                    <?= e(status_zakaza_podpis($z['status'])) ?>
                </span></td>
                <td><a href="zakaz.php?id=<?= (int) $z['id'] ?>">Подробнее</a></td>
            </tr>
        <?php endforeach; ?>
        </tbody>
    </table>
<?php endif; ?>

<?php require __DIR__ . '/includes/footer.php'; ?>
```

### **Подписи статусов**

```php
function status_zakaza_podpis(string $status): string
{
    return match ($status) {
        'novyi'        => 'Новый',
        'podtverzhden' => 'Подтверждён',
        'sobran'       => 'Собран',
        'otpravlen'    => 'Отправлен',
        'dostavlen'    => 'Доставлен',
        'otmenen'      => 'Отменён',
        default        => 'Неизвестно',
    };
}
```

Помните правило из главы 21: **в базе код, на экране перевод**. Захотите
поменять формулировку — правите одну функцию, а не тысячу записей.

## 📖 Страница 403

```php
<?php
// 403.php
$zagolovok = 'Доступ закрыт';
require __DIR__ . '/includes/header.php';
?>

<div class="pusto">
    <h1>Сюда нельзя</h1>
    <p>У вас нет прав на эту страницу.</p>
    <?php if (!voshel()): ?>
        <p>Возможно, нужно войти под другим аккаунтом.</p>
        <a class="knopka" href="/vhod.php">Войти</a>
    <?php else: ?>
        <a class="knopka" href="/">На главную</a>
    <?php endif; ?>
</div>

<?php require __DIR__ . '/includes/footer.php'; ?>
```

⚠️ **403 и 404 — разные вещи, и разница не только формальная.**

- **404** — «такой страницы нет»;
- **403** — «страница есть, но вам нельзя».

Иногда 403 намеренно заменяют на 404: чтобы посторонний даже не узнал,
что такой раздел существует. Для админки это разумная предосторожность.

## 📖 Журнал действий

Для ролей выше покупателя полезно записывать, кто что сделал:

```php
function zapisat_deystvie(string $deystvie, string $obekt = '', int $obekt_id = 0): void
{
    $ya = tekushiy_polzovatel();

    vypolnit('
        INSERT INTO zhurnal (polzovatel_id, deystvie, obekt, obekt_id, ip, sozdan)
        VALUES (?, ?, ?, ?, ?, NOW())
    ', [
        $ya['id'] ?? null,
        $deystvie,
        $obekt,
        $obekt_id,
        $_SERVER['REMOTE_ADDR'] ?? '',
    ]);
}

// Использование
zapisat_deystvie('izmenil_cenu', 'tovar', $tovar_id);
zapisat_deystvie('otmenil_zakaz', 'zakaz', $zakaz_id);
```

**Зачем это нужно** — три причины, каждая проверена практикой:

1. **Разбор спорных ситуаций.** «Кто снизил цену на аккумуляторы?» — вопрос,
   который однажды прозвучит.
2. **Обнаружение взлома.** Странная активность видна в журнале.
3. **Просто дисциплина.** Люди аккуратнее, когда знают, что действия
   записываются.

Записывайте **действия, меняющие данные**. Просмотры писать не надо — журнал
распухнет и станет бесполезным.

## 📖 Что защищать в первую очередь

Список мест, где чаще всего забывают проверку:

| Место | Что проверить |
|---|---|
| Страницы админки | Роль не ниже `manager` |
| Кабинет продавца | Роль `prodavec` **и владение** |
| Редактирование товара | Владение |
| Просмотр заказа | Свой заказ или менеджер |
| Точки `api/` | **Те же права, что у страниц** |
| Скачивание файлов | Право на этот файл |
| Действия POST | Роль **и** CSRF |

⚠️ **Точки `api/` забывают чаще всего.** Кажется, что это «внутренний»
адрес, — но он открыт всему интернету так же, как обычная страница.

Каждый файл в `api/` — полноценная точка входа и требует тех же проверок.

## 🔤 Разбор по словам

| Запись | Что делает |
|---|---|
| `rol()` | Роль текущего пользователя или `gost` |
| `rol_est('admin')` | Роль ровно такая |
| `rol_ne_nizhe('manager')` | Роль не ниже по иерархии |
| `trebuetsya_vhod()` | Не вошёл — на страницу входа |
| `trebuetsya_rol('manager')` | Мало прав — 403 |
| **IDOR** | Доступ к чужому объекту по подобранному номеру |
| Фильтр владения в запросе | Чужое просто не находится |
| `http_response_code(403)` | «Есть, но нельзя» |
| `zapisat_deystvie()` | Журнал изменений |

## ⚠️ Грабли

**Прятать ссылку вместо проверки.** Адрес наберут руками.

**Проверять только роль, не владение.** IDOR: чужие товары и заказы.

**Проверка не первой строкой.** Часть работы выполнится до неё.

**Забыть защитить `api/`.** Открытая дверь рядом с запертой.

**Хранить роль в куке или в скрытом поле формы.** Перепишут за секунду.
Роль — **только из базы**, по идентификатору из сессии.

**Не перепроверять роль при каждом запросе.** Пользователя могли заблокировать
пять минут назад.

**Один общий аккаунт на всех сотрудников.** Журнал станет бесполезным.

## 🔗 В бою

Откройте `admin/` и `seller/` в этом репозитории. В начале каждого файла —
проверка прав, до всякой логики.

Особенно посмотрите на кабинет продавца. Там владение проверяется **в самих
запросах**: продавец получает список своих товаров запросом с условием
`WHERE prodavec_id = ?`, а не «достанем всё и отфильтруем».

И одна деталь из CLAUDE.md проекта: сбор данных каталога от поставщика виден
**только суперадмину**. Покупатель не должен знать ни имени поставщика,
ни остатка квоты, ни того, что магазин что-то собирает.

Разграничение доступа — это не только про безопасность. Это ещё и про то,
чтобы не показывать людям лишнего.

## 📌 Итог

- **Прятать ссылку — не защита.** Проверка на сервере, **первой строкой**.
- Роль отвечает «кто ты», владение — «твоё ли это». Нужны обе проверки.
- **IDOR** — доступ к чужому по подобранному номеру. Самая частая дыра
  в кабинетах.
- Лучший способ — **фильтр владения прямо в запросе**: чужое не находится.
- Роль берите **из базы**, а не из куки или формы.
- `api/` защищайте так же, как страницы.
- **403** — «нельзя», **404** — «нет». Для админки можно намеренно отдавать 404.
- Записывайте в журнал действия, меняющие данные.
- В базе код статуса, на экране перевод.
