# Глава 51. Курсы валют и наценки

> **Часть X. Внешний мир** · Глава 51 из 60

## 🎯 Зачем эта глава

Поставщик отдал цену: **4300 рублей**. Покупателю нужно показать цену в сомони.

Кажется, задача на одно умножение. На деле в эту цифру входит:

- курс рубля к сомони — который меняется каждый день;
- ваша наценка — которая должна покрыть работу и риск;
- доставка от поставщика до вашего города;
- округление — чтобы цена выглядела прилично;
- запас на колебание курса, пока товар едет.

Ошибка в любом из шагов означает работу в убыток. Причём заметите вы это
не сразу, а когда сведёте месяц.

Разберём, как построить расчёт, который не подведёт.

## 📖 Порядок расчёта

Порядок операций важен: от него зависит итог.

```
Цена поставщика в рублях
    ↓ × курс
Цена в сомони (закупочная)
    ↓ + доставка до вашего склада
Себестоимость
    ↓ × наценка
Цена продажи
    ↓ округление
Цена на витрине
```

⚠️ **Доставка прибавляется до наценки, а не после.**

Разница существеннее, чем кажется:

| Порядок | Расчёт | Итог |
|---|---|---|
| Доставка **до** наценки | (4300×1.15 + 80) × 1.35 = | **6784 сомони** |
| Доставка **после** наценки | 4300×1.15×1.35 + 80 = | **6754 сомони** |

Тридцать сомони с позиции. На тысяче заказов — тридцать тысяч.

**Логика такая: наценка покрывает вашу работу и риск, а доставка — часть
себестоимости.** Вы вложили в товар и деньги за него, и деньги за доставку,
и наценка должна начисляться на всё вложенное.

## 💻 Расчёт цены

```php
<?php
// includes/cenoobrazovanie.php
declare(strict_types=1);

/**
 * Цена для покупателя из цены поставщика.
 *
 * Все внутренние расчёты — в дирамах, целыми числами.
 * Округление один раз, в самом конце.
 */
function cena_dlya_pokupatelya(float $cena_rub, array $nastroyki = []): int
{
    $kurs      = $nastroyki['kurs']       ?? kurs_rublya();
    $nacenka   = $nastroyki['nacenka']    ?? (float) nastroyka('nacenka_procent', '35');
    $dostavka  = $nastroyki['dostavka']   ?? (int) nastroyka('dostavka_diram', '8000');
    $zapas     = $nastroyki['zapas_kursa'] ?? (float) nastroyka('zapas_kursa_procent', '3');

    // 1. Рубли в дирамы. Запас на колебание курса, пока товар едет
    $kurs_s_zapasom = $kurs * (1 + $zapas / 100);
    $zakupka_diram = $cena_rub * 100 * $kurs_s_zapasom;

    // 2. Доставка до нашего склада — часть себестоимости
    $sebestoimost = $zakupka_diram + $dostavka;

    // 3. Наценка на всю себестоимость
    $cena = $sebestoimost * (1 + $nacenka / 100);

    // 4. Округление — один раз, в конце
    return okruglit_cenu((int) round($cena));
}

/**
 * Округление до «красивого» значения.
 * 6784 сомони выглядит как результат работы калькулятора,
 * 6790 — как цена.
 */
function okruglit_cenu(int $diram): int
{
    $somoni = $diram / 100;

    if ($somoni < 10)   return (int) (ceil($somoni) * 100);          // до сомони
    if ($somoni < 100)  return (int) (ceil($somoni / 5) * 5 * 100);  // до 5
    if ($somoni < 1000) return (int) (ceil($somoni / 10) * 10 * 100); // до 10
    return (int) (ceil($somoni / 50) * 50 * 100);                     // до 50
}
```

### **Про запас на курс**

Строчка, которую обычно забывают:

```php
$kurs_s_zapasom = $kurs * (1 + $zapas / 100);
```

Зачем: между тем, как покупатель увидел цену, и тем, как вы фактически
заплатите поставщику, проходит время — от нескольких дней до нескольких недель.
Курс за это время может вырасти.

Три процента запаса покрывают обычные колебания. Без него при росте курса
вы продаёте в убыток, ничего об этом не зная.

⚠️ **Только `ceil` при округлении, никогда `round`.**

`round(6784)` до десятков даст 6780 — вы потеряли 4 сомони. На тысяче позиций
это 4000 сомони чистого убытка просто из-за выбора функции.

**Округление цены всегда вверх.** Это не жадность, а защита от накопления
потерь на округлении.

## 📖 Настройки, а не константы

Наценка, курс, доставка — то, что владелец магазина захочет менять сам.
Причём часто.

```php
// ❌ Меняется правкой кода и выкладкой
const NACENKA = 35;

// ✅ Меняется в админке за минуту
$nacenka = (float) nastroyka('nacenka_procent', '35');
```

```php
// admin/nastroyki.php
$polya = [
    'nacenka_procent'     => ['Наценка, %', 'Основная наценка на товары поставщика'],
    'dostavka_diram'      => ['Доставка до склада, дирамы', 'Надбавка Москва → Худжанд'],
    'zapas_kursa_procent' => ['Запас на курс, %', 'Защита от роста курса, пока товар едет'],
    'kurs_zapasnoy'       => ['Запасной курс', 'Если сервис курсов недоступен'],
];
```

**Правило: всё, что зависит от бизнеса, а не от кода, — в настройки.**

Наценка, сроки, минимальная сумма заказа, стоимость доставки, тексты писем.
Каждая такая настройка — это задача, которую владелец решит сам, не отвлекая
вас.

## 📖 Разные наценки для разных случаев

Одна наценка на всё — упрощение, которое быстро перестаёт работать.

```php
function nacenka_dlya_tovara(array $tovar): float
{
    // 1. Индивидуальная наценка товара — если задана
    if (!empty($tovar['nacenka_procent'])) {
        return (float) $tovar['nacenka_procent'];
    }

    // 2. Наценка категории
    if (!empty($tovar['kategoriya_id'])) {
        $po_kategorii = zapros_znachenie('
            SELECT nacenka_procent FROM kategorii WHERE id = ?
        ', [$tovar['kategoriya_id']]);

        if ($po_kategorii !== null && $po_kategorii !== '') {
            return (float) $po_kategorii;
        }
    }

    // 3. Наценка по диапазону цены
    $cena_rub = (float) ($tovar['cena_postavshika'] ?? 0);
    $diapazony = json_decode(nastroyka('nacenki_po_cene', '[]'), true) ?: [];

    foreach ($diapazony as $d) {
        if ($cena_rub >= ($d['ot'] ?? 0) && $cena_rub < ($d['do'] ?? PHP_INT_MAX)) {
            return (float) $d['nacenka'];
        }
    }

    // 4. Общая наценка
    return (float) nastroyka('nacenka_procent', '35');
}
```

**Почему наценка зависит от цены.** На дешёвых товарах процент должен быть
выше: обработка заказа на 50 сомони и на 5000 стоит одинаково.

Типичная шкала:

| Цена поставщика | Наценка |
|---|---|
| до 500 руб. | 60% |
| 500–2000 | 45% |
| 2000–10 000 | 35% |
| свыше 10 000 | 25% |

На дорогих товарах процент ниже, но абсолютная прибыль выше — и цена
остаётся конкурентной.

## 📖 Показывать ли, из чего сложилась цена

Короткий ответ: **нет**.

Покупателю показывают итоговую цену. Закупочная цена, наценка и курс —
коммерческая тайна.

```php
// ❌ Никогда так не делайте
<div data-zakupka="<?= $tovar['cena_postavshika'] ?>"
     data-nacenka="<?= $nacenka ?>">
    <?= somoni($cena) ?> сомони
</div>
```

Помните главу 19: то, что попало в HTML, видно всем. Покупатель откроет код
страницы, увидит закупочную цену и пойдёт к поставщику напрямую.

**В браузер уходит только итоговая цена.** Всё остальное остаётся на сервере.

⚠️ Это касается и `data-` атрибутов, и JavaScript-переменных, и ответов API.
Проверьте свой API: не отдаёт ли он лишние поля вместе с ценой?

## 📖 История цен

Цены поставщика меняются. Полезно сохранять историю:

```sql
CREATE TABLE istoriya_cen (
    id           INT AUTO_INCREMENT PRIMARY KEY,
    artikul      VARCHAR(64) NOT NULL,
    cena_rub     DECIMAL(10,2) NOT NULL,
    kurs         DECIMAL(10,4) NOT NULL,
    cena_diram   INT NOT NULL COMMENT 'итоговая, для покупателя',
    zafiksirovano DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,

    KEY idx_artikul_data (artikul, zafiksirovano)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

Зачем:

- **разобраться в споре**: «у вас вчера было дешевле» — можно проверить;
- **увидеть, что дорожает**: поставщик поднял цены на 20% — заметно сразу;
- **посчитать реальную маржу**: продали по одной цене, купили по другой;
- **предупредить покупателя**: «цена выросла, но у нас осталась старая».

⚠️ Не записывайте цену при каждом обращении к API — таблица распухнет.
Записывайте, **только если цена изменилась**:

```php
function zafiksirovat_cenu(string $artikul, float $cena_rub,
                           float $kurs, int $cena_diram): void
{
    $poslednyaya = zapros_odin('
        SELECT cena_rub FROM istoriya_cen
        WHERE artikul = ? ORDER BY zafiksirovano DESC LIMIT 1
    ', [$artikul]);

    // Цена та же — не плодим записи
    if ($poslednyaya !== null
        && abs((float) $poslednyaya['cena_rub'] - $cena_rub) < 0.01) {
        return;
    }

    vypolnit('
        INSERT INTO istoriya_cen (artikul, cena_rub, kurs, cena_diram)
        VALUES (?, ?, ?, ?)
    ', [$artikul, $cena_rub, $kurs, $cena_diram]);
}
```

## 📖 Проверьте расчёт числами

Прежде чем запускать, посчитайте вручную и сверьте.

**Дано:** цена поставщика 4300 руб., курс 1.15, запас 3%, доставка 80 сомони,
наценка 35%.

```
1. Курс с запасом:     1.15 × 1.03 = 1.1845
2. Закупка в дирамах:  4300 × 100 × 1.1845 = 509 335
3. Себестоимость:      509 335 + 8000 = 517 335
4. С наценкой:         517 335 × 1.35 = 698 402
5. В сомони:           6984.02
6. Округление вверх до 50: 7000.00
```

**Цена на витрине: 7000 сомони.**

```php
function proverit_raschet(): void
{
    $cena = cena_dlya_pokupatelya(4300.0, [
        'kurs' => 1.15, 'nacenka' => 35.0,
        'dostavka' => 8000, 'zapas_kursa' => 3.0,
    ]);

    $ozhidaemo = 700000;   // 7000 сомони в дирамах

    if ($cena !== $ozhidaemo) {
        throw new RuntimeException(sprintf(
            'Расчёт цены сломан: ожидали %s, получили %s',
            somoni($ozhidaemo), somoni($cena)
        ));
    }
}
```

**Такая проверка — простейший вид теста.** Она поймает случай, когда кто-то
поменяет порядок операций «для красоты» и незаметно изменит все цены.

Для расчётов, связанных с деньгами, подобные проверки стоит писать всегда.

## 🔤 Разбор по словам

| Запись | Что означает |
|---|---|
| Доставка **до** наценки | Наценка начисляется на всю себестоимость |
| Запас на курс | Защита от роста, пока товар едет |
| `ceil` при округлении | **Всегда вверх**, иначе накопится убыток |
| Округление один раз | В конце цепочки, не на каждом шаге |
| `nastroyka()` | Значения из базы, меняются в админке |
| Наценка по диапазону | На дешёвом товаре процент выше |
| `istoriya_cen` | Записываем, только если цена изменилась |

## ⚠️ Грабли

**Доставка после наценки.** Теряете деньги на каждой позиции.

**`round` вместо `ceil`.** Копейки вниз накапливаются в убыток.

**Округление на каждом шаге.** Расхождение с расчётом.

**Нет запаса на курс.** Курс вырос — работаете в минус.

**Наценка в константе.** Владелец не может изменить без программиста.

**Одна наценка на всё.** На дешёвых товарах не окупается обработка заказа.

**Закупочная цена в HTML или API.** Покупатель уйдёт к поставщику.

**Не проверять расчёт числами.** Ошибку заметите при сведении месяца.

**Писать историю цен на каждое обращение.** Таблица распухнет.

## 🔗 В бою

Откройте `includes/catalog/AutoEuroPriceProvider.php` в этом репозитории.
Там ровно эта цепочка: рубли → курс → наценка → надбавка Москва—Худжанд.

Обратите внимание на отдельную надбавку за доставку из Москвы в Худжанд —
она вынесена отдельными настройками. Причина простая: доставка зависит
от веса и габаритов, и для тяжёлых позиций она другая.

Все настройки — наценка, курс, надбавки — редактируются через суперадминку.
Владелец магазина меняет их сам, когда меняются условия поставщика или курс.

**Это и есть признак законченного продукта:** не «позвоните программисту»,
а «зайдите в настройки».

## 📌 Итог

- Порядок расчёта: **рубли → курс → доставка → наценка → округление**.
- **Доставка прибавляется до наценки** — она часть себестоимости.
- **Запас на курс** защищает от роста, пока товар едет.
- Округление **вверх** (`ceil`) и **один раз**, в конце.
- Наценка, курс, доставка — **в настройках**, не в константах.
- Наценка **зависит от цены**: на дешёвом товаре процент выше.
- **Закупочная цена не должна попадать** ни в HTML, ни в API.
- Историю цен пишем **только при изменении**.
- **Проверяйте расчёт числами** — это простейший тест для денег.
