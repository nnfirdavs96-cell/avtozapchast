# Приложение Б. 30 ошибок новичка

> **Симптом → причина → лечение** · Приложение Б

Тридцать ситуаций, на которые уходит больше всего времени в первый год.
Все они встречаются у каждого — разница только в том, сколько часов
занимает разгадка.

Пользоваться так: найдите **симптом** — то, что видите на экране. Дальше
читайте причину и лечение.

---

## HTML и вёрстка

### 1. Страница показывает кракозябры вместо русских букв

**Симптом.** Вместо «Фильтр» — `Ð¤Ð¸Ð»ÑŒÑ‚Ñ€` или `?????`.

**Причина.** Не указана кодировка — где-нибудь в цепочке. Мест три:
страница, база, соединение с базой.

**Лечение.** Все три сразу:

```html
<meta charset="utf-8">                       <!-- в <head> -->
```
```php
$dsn = 'mysql:host=localhost;dbname=magazin;charset=utf8mb4';   // в PDO
```
```sql
CREATE TABLE ... DEFAULT CHARSET=utf8mb4;    -- в базе
```

Плюс сам файл должен быть сохранён в UTF-8 (в редакторе — «UTF-8 without BOM»).

### 2. Стили не применяются

**Симптом.** CSS написан, а страница не меняется.

**Причина.** Одно из трёх: неверный путь к файлу, кэш браузера, или ваш
селектор проиграл более сильному.

**Лечение.** По порядку: F12 → Network — файл загрузился (200, не 404)?
Затем Ctrl+F5 (сброс кэша). Затем F12 → Elements → выберите элемент
и посмотрите, какое правило зачёркнуто и кем перебито.

### 3. Форма отправляется, а на сервере пусто

**Симптом.** `$_POST` пустой.

**Причина.** Почти всегда — у полей нет атрибута `name`. Либо у формы
`method="get"`, а вы читаете `$_POST`.

**Лечение.** У каждого поля — `name`. Проверить: `var_dump($_POST);`
в начале обработчика.

### 4. Кнопка внутри формы перезагружает страницу

**Симптом.** Нажали кнопку — страница мигнула, всё сбросилось.

**Причина.** `<button>` внутри `<form>` по умолчанию — это `type="submit"`.

**Лечение.** Если кнопка не для отправки: `<button type="button">`.
Если обрабатываете отправку скриптом: `e.preventDefault()`.

### 5. Картинки не видны на сервере, хотя локально были

**Симптом.** Локально всё есть, на хостинге — битые картинки.

**Причина.** Разный регистр в имени файла. Windows не различает
`Filtr.JPG` и `filtr.jpg`, Linux — различает.

**Лечение.** Все имена файлов — маленькими буквами, латиницей, без пробелов.

### 6. Вёрстка разъезжается на телефоне

**Симптом.** На компьютере хорошо, на телефоне — горизонтальная прокрутка.

**Причина.** Нет `viewport`, либо жёсткие ширины в пикселях.

**Лечение.** `<meta name="viewport" content="width=device-width, initial-scale=1">`
и `max-width` вместо `width`. Проверять в F12 → режим устройства.

## CSS

### 7. `width: 100%` вылезает за экран

**Симптом.** Блок шире родителя ровно на величину отступов.

**Причина.** По умолчанию `padding` и `border` **прибавляются** к `width`.

**Лечение.** Один раз на весь проект:

```css
*, *::before, *::after { box-sizing: border-box; }
```

### 8. Отступы между блоками «слиплись»

**Симптом.** Задали `margin-bottom: 20px` и `margin-top: 30px`, получили 30,
а не 50.

**Причина.** Схлопывание вертикальных отступов — так работает CSS.

**Лечение.** Используйте отступ **в одну сторону** (обычно `margin-bottom`),
либо `gap` во flex/grid — там схлопывания нет.

### 9. `z-index` не работает

**Симптом.** Поставили `z-index: 9999`, элемент всё равно снизу.

**Причина.** `z-index` действует только на позиционированных элементах.

**Лечение.** Добавьте `position: relative` (или `absolute`/`fixed`).

### 10. Не могу центрировать блок

**Симптом.** `text-align: center` не центрирует блок.

**Лечение.** Три рабочих способа:

```css
.blok  { margin: 0 auto; max-width: 600px; }        /* по горизонтали */
.roditel { display: flex; justify-content: center; align-items: center; }
.roditel { display: grid; place-items: center; }    /* по обеим осям */
```

## JavaScript

### 11. `Cannot read properties of null`

**Симптом.** Скрипт падает на первой же строке с элементом.

**Причина.** `querySelector` ничего не нашёл — опечатка в селекторе или
скрипт выполняется **раньше**, чем разметка загрузилась.

**Лечение.** Скрипт — перед `</body>` или с `defer`. И проверка:

```js
const el = document.querySelector('#itog');
if (!el) { console.error('нет элемента #itog'); return; }
```

### 12. Обработчик не срабатывает на новых элементах

**Симптом.** Кнопки, добавленные скриптом, не реагируют.

**Причина.** `addEventListener` навесили на существующие элементы,
а новые появились позже.

**Лечение.** Делегирование — один обработчик на контейнер:

```js
spisok.addEventListener('click', (e) => {
    const knopka = e.target.closest('.kupit');
    if (knopka) dobavit(knopka.dataset.id);
});
```

### 13. `0.1 + 0.2` даёт `0.30000000000000004`

**Симптом.** Итог корзины — `1325.0000000000002`.

**Причина.** Дробные числа в компьютере хранятся приближённо. Это
не баг языка, так везде.

**Лечение.** **Деньги хранить в целых** — в дирамах, копейках, центах.
Делить на 100 только при выводе.

### 14. `fetch` не работает, в консоли CORS

**Симптом.** `Access to fetch ... has been blocked by CORS policy`.

**Причина.** Браузер запрещает запросы к чужому домену без разрешения.

**Лечение.** Ходите к **своему** серверу, а он пусть ходит к чужому API
(глава 50). Заодно ключ API не попадёт в браузер.

### 15. `this` внутри функции — не то, что ожидалось

**Причина.** У обычной функции `this` зависит от того, **как её вызвали**.

**Лечение.** Пользуйтесь стрелочными функциями — в них `this` берётся
из окружающего кода: `el.addEventListener('click', () => { ... })`.

### 16. Данные пропали после обновления страницы

**Симптом.** Корзина очищается по F5.

**Причина.** Данные жили только в переменной JavaScript.

**Лечение.** `localStorage` (глава 18) или сессия на сервере (глава 38).

## PHP

### 17. Белый экран, никаких сообщений

**Причина.** Ошибка есть, но её показ выключен.

**Лечение.** На своей машине включить:

```php
ini_set('display_errors', '1');
error_reporting(E_ALL);
```

На боевом — наоборот, выключить и смотреть в лог (глава 56).

### 18. `Headers already sent`

**Симптом.** Ошибка при `header()`, `session_start()` или `setcookie()`.

**Причина.** До них что-то уже вывелось: пробел или пустая строка
**перед** `<?php`, лишний перевод строки после `?>` в подключённом файле,
случайный `echo`.

**Лечение.** В файлах только с PHP-кодом **не закрывайте** тег `?>` —
тогда лишнего вывода не будет. И проверьте, нет ли пробела в первой строке.

### 19. `Call to a member function prepare() on null`

**Причина.** `$pdo` не создался — обычно подключение к базе не удалось,
а ошибку никто не проверил.

**Лечение.** Подключение — в `try/catch` с `ERRMODE_EXCEPTION`, и проверять
результат до использования.

### 20. Запрос не находит ничего, хотя данные есть

**Симптом.** `SELECT` возвращает пусто, а в базе строки видны.

**Причина.** Варианты: лишние пробелы в данных, разный регистр, ищете
по началу строки (`LIKE 'x%'`) вместо вхождения (`LIKE '%x%'`), либо
подключились не к той базе.

**Лечение.** Выведите сам запрос и параметры (`var_dump($sql, $params)`)
и выполните его руками в базе.

### 21. Числа из формы ведут себя как строки

**Симптом.** `'5' + 5` вроде работает, а сравнение — нет.

**Причина.** Из `$_POST` **всегда** приходят строки.

**Лечение.** Приводите явно и с проверкой:

```php
$kol = max(1, (int) ($_POST['kol'] ?? 1));
$cena = (float) ($_POST['cena'] ?? 0);
```

### 22. Заказ записался дважды

**Симптом.** Покупатель нажал F5 — заказ продублировался.

**Причина.** Обработка формы и вывод страницы в одном запросе.

**Лечение.** Паттерн **POST → Redirect → GET**: после успешной записи —
`header('Location: /spasibo.php?id=' . $id); exit;`

### 23. Сессия «слетает»

**Симптом.** Пользователь то входит, то нет.

**Причина.** `session_start()` вызывается не на всех страницах, либо
вызывается после вывода, либо на сайте гуляют два адреса — с `www` и без.

**Лечение.** `session_start()` — первой строкой общего файла подключений.
И редирект с `www` на основной домен (глава 58).

### 24. `undefined array key` при каждом заходе

**Причина.** Ключа в массиве нет — например, при первом заходе на страницу.

**Лечение.** Оператор `??`:

```php
$stranica = (int) ($_GET['stranica'] ?? 1);
$imya = trim($_POST['imya'] ?? '');
```

## База данных

### 25. `UPDATE` изменил всю таблицу

**Симптом.** Хотели поменять один товар — поменялись все.

**Причина.** Забыт `WHERE`.

**Лечение.** Привычка: пишем `WHERE` **первым**, потом всё остальное.
И бэкап перед любыми массовыми изменениями. Восстановление —
только из бэкапа: отменить `UPDATE` нельзя.

### 26. Сайт тормозит по мере роста базы

**Симптом.** Каталог грузился 0.1 с, теперь 3 с.

**Причина.** Нет индексов на столбцах, по которым идёт поиск.

**Лечение.** `EXPLAIN` на медленном запросе; индекс на столбцы из `WHERE`,
`JOIN`, `ORDER BY` (глава 30 — там реальный замер: 314-кратное ускорение).

### 27. Кириллица в базе превратилась в `?`

**Причина.** Кодировка таблицы или соединения — не `utf8mb4`.

**Лечение.** См. ошибку №1. Данные, уже записанные знаками вопроса,
восстановить нельзя — только перезалить.

### 28. Сломался JOIN: строк стало больше, чем товаров

**Симптом.** 100 товаров, а запрос вернул 340 строк.

**Причина.** У товара несколько связанных записей (например, отзывов) —
`JOIN` умножает строки.

**Лечение.** `GROUP BY` с агрегатом (`COUNT`, `SUM`) либо подзапрос.

## Безопасность и деньги

### 29. SQL-инъекция

**Симптом.** Обычно никакого — до дня, когда база утекла.

**Причина.** Значения склеены со строкой запроса:

```php
// ТАК НЕЛЬЗЯ НИКОГДА
$pdo->query("SELECT * FROM users WHERE email = '$email'");
```

**Лечение.** Только подготовленные запросы:

```php
$stmt = $pdo->prepare('SELECT * FROM users WHERE email = ?');
$stmt->execute([$email]);
```

Никаких исключений — даже «тут же число», даже «это админка».

### 30. Пароль или ключ API уехал в git

**Симптом.** Ничего не видно, но через неделю с вашего аккаунта у поставщика
идут чужие запросы.

**Причина.** Файл с секретом закоммитили. Удаление файла не помогает —
он остался в истории, а публичные репозитории боты сканируют за минуты.

**Лечение.** Считать секрет **скомпрометированным** и сменить его. Дальше —
`.gitignore` с первого дня и секреты в настройках базы (глава 57).

## Три привычки, которые заменяют половину этого списка

1. **Читать сообщение об ошибке целиком.** В нём написано что, где
   и в какой строке. Большинство пунктов выше решаются первым же
   прочтением текста ошибки.
2. **Проверять границы.** Данные проходят путь форма → PHP → база →
   PHP → браузер. Выведите значение на каждой границе — увидите,
   где именно оно пропало.
3. **Коммитить до эксперимента.** Пока изменения в git, любой тупик
   отменяется одной командой. Без git — потерянный вечер.
